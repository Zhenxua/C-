## 1. 问题陈述

在法国找工作的人，特别是外国人和应届生（留学生、持 APS / Passeport Talent 的求职者），**投递和签约之前很难了解一家公司的真实情况**：

- **信息分散**：工商数据在 Pappers / Société.com，评价在 Glassdoor / Indeed，平等指数在劳动部网站，经验贴在小红书、微信群和 Reddit。
- **信息不对称**：招聘页只写好话。CDD 转 CDI 的概率、période d'essai（试用期）期间解约的频率、是否愿意办工签、真实薪资、加班和 forfait jours（按天计薪制）的实际执行情况，都很难事先知道。
- **外国求职者被坑的代价更高**：居留身份和雇主绑定，被拖欠工资、试用期被随意解约、工签材料被拖延，都直接影响能否留在法国。
- **现有平台不贴合**：Glassdoor 以英语和美国视角为主，法国中小企业覆盖少；中文社群的信息不能检索、不能核实、很快就过时。

**一句话**：求职者需要一个**可检索、有证据、按法国语境组织**的公司口碑和风险档案，在投简历、面试、谈 offer 时帮自己做决定。

## 2. 目标用户

| 画像 | 描述 | 核心诉求 |
|---|---|---|
| P1 在法留学生 / 应届生（主要用户） | M1/M2 学生，在找 stage（实习）、alternance（工学交替）或第一份 CDI | 实习给不给转正、工资有没有按法定 gratification 发、会不会办 changement de statut（学生居留转工作居留） |
| P2 外籍跳槽者 | 在法国工作 1–5 年的工程师和数据人员 | 薪资对标、团队氛围、对外国人是否友好、裁员（PSE / rupture conventionnelle）历史 |
| P3 海外求职者 | 人还不在法国，想拿 offer 后办签证过来 | 公司是否真实存在、财务状况是否稳健、有没有为外国人担保签证的记录 |
| P4 贡献者 | 在职或离职员工 | 匿名、安全地分享经历，不担心被报复 |

以上画像都限定为**使用中文的求职者**（以华人留学生和在法华人职场人为主）。

非目标用户：HR / 雇主方。MVP 不提供雇主账号，也永远不做付费的雇主品牌服务，以保证中立。

## 4. 关键设计原则

1. **证据优先，不搞"人身攻击榜"**："红黑榜"只是对外传播的叫法。产品里用**客观标签和评分**呈现，比如"🟢 推荐 / 🟡 注意 / 🔴 高风险"，每个标签都必须能追溯到具体来源：公开数据或多条评价。
2. **公开数据和 UGC 分开**：官方数据（事实）与用户评价（观点）在界面上明确区分，降低诽谤（diffamation）风险。
3. **匿名但可信**：对外完全匿名；对内通过邮箱域名或文件做**可选的雇佣关系验证**，验证过的评价权重更高。
4. **法国语境原生**：评价维度按法国劳动法和职场文化设计，而不是照搬 Glassdoor。
5. **中文优先**：界面只有中文；法语专有名词（CDI、période d'essai、RTT 等）保留原文，并配中文解释浮层，帮用户同时熟悉法国职场用语。
6. **非营利中立**：不接受任何公司的付费推广、置顶或删评请求；运营成本靠捐赠和志愿者，财务每年公开。

## 5. 功能需求

### 5.1 公司档案页（核心）

每家公司以 **SIREN** 作为唯一 ID，分以下几块：

**A. 官方事实区（自动抓取，标注来源和更新日期）**

| 数据 | 来源 | 用途 |
|---|---|---|
| 基本信息：名称、SIREN/SIRET、NAF 行业代码、员工规模、成立日期、地址、状态（在营 / 注销） | INSEE SIRENE API（开放） | 判断公司是否真实存在、规模多大 |
| 财报：营收、净利润（如已公开） | INPI RNE / 已公开的年报 ⚠️ 不少中小企业选择不公开 | 看财务是否健康 |
| 集体程序：sauvegarde、redressement、liquidation judiciaire（保护、重整、清算程序） | BODACC（开放数据） | **🔴 强风险信号** |
| 男女职业平等指数 Index égalité professionnelle | 劳动部开放数据 Egapro（员工 ≥ 50 人的公司） | 看男女同工同酬情况 |
| 违法用工处罚公示（如 travail dissimulé，即非法用工） ⚠️ 需确认公示渠道和保留期限 | 劳动部 / 法院公开信息 | **🔴 强风险信号** |
| 付款延迟处罚（DGCCRF 公示） | economie.gouv.fr | 侧面反映公司的诚信 |
| 适用的集体协议 Convention collective (IDCC) | SIRET ↔ IDCC 对照的开放数据 | 帮用户查最低工资和福利 |

**B. 社区评价区（UGC）**

- 综合评分（1–5 星）和分项评分：
  - 薪资与福利（tickets resto 餐券、mutuelle 补充医保、prime 奖金、intéressement / participation 利润分享）
  - 工作与生活平衡（RTT 年假补偿、远程办公、forfait jours 下的实际工时）
  - 管理与氛围
  - 职业发展 / 转正（CDD→CDI、stage→CDI）
  - **外国人友好度**：会不会办工签、HR 是否熟悉 APS / changement de statut 流程、工作语言
- 结构化字段：职位、部门、城市、合同类型（CDI/CDD/Stage/Alternance/Intérim/Freelance）、在职 / 离职、年份区间（只精确到年，保护匿名）
- 文本：优点 / 缺点 / 给管理层的建议
- 有用 / 无用投票，举报入口

**C. 面试经验区**：流程轮次、题目类型、用时、结果、体验评分。

**D. 薪资数据区**：职位 + 城市 + 经验年限 + brut annuel（税前年薪，含 variable 浮动部分）。少于 5 条时**不展示具体数值**，以保护匿名。

**E. 签证担保记录**（差异化功能）：用户上报"该公司为我办理了 Passeport Talent / 工作居留 / changement de statut"，展示次数和年份分布。

**F. 雇主申诉**：公司不能在小程序内回复评价（目标用户只是中文社区，MVP 不做雇主账号）。公司可以通过公开的法律联系邮箱举报违法内容，由人工按下架流程处理。

### 5.2 红黑榜 / 风险标签机制

标签自动计算、规则公开（在"评分方法论"页面公示）：

| 标签 | 触发规则（初稿） ⚠️ |
|---|---|
| 🔴 **高风险** | 处于集体程序中，**或者**有违法用工处罚公示，**或者** 12 个月内 ≥ 3 条独立且已验证的评价提到"拖欠工资 / 未支付 gratification / 非法解约" |
| 🟡 **注意** | 近 12 个月综合评分 < 2.5（至少 5 条评价）；或分项"转正"评分 < 2；或 Egapro < 75 分 |
| 🟢 **推荐** | 综合评分 ≥ 4.0（至少 10 条评价，其中至少 3 条已验证），且没有任何 🔴 信号 |
| ⚪ **数据不足** | 不满足以上条件时的默认状态 |

- 榜单页面：按行业、省份（巴黎大区八省）、规模、外国人友好度筛选的"红榜 Top / 风险提示"列表。
- **"黑榜"只展示有官方数据支撑的 🔴**，纯 UGC 驱动的负面标签只出现在公司页内，不进公开榜单，以降低法律风险。

### 5.3 搜索与发现

- 按公司名、SIREN、品牌名（处理"商号 ≠ 法人名"的问题，例如集团子公司）搜索
- 筛选：省份 / 城市（MVP 只有巴黎大区）、行业（NAF）、规模、合同类型、是否有签证担保记录
- 支持中文别名搜索，例如"兴业"→ Société Générale、"欧莱雅"→ L'Oréal（别名表由社区共建，人工审核）
- 公司对比：最多 3 家并排比较（用户谈 offer 时很有用）

### 5.4 贡献与审核

- 登录：微信授权登录。后端只保存加盐哈希后的 openid，**不获取头像、昵称或手机号**；评价对外只显示"匿名用户 #随机编号"，同一用户在不同公司下的编号也不同，防止被串联认出。
- 可选的雇佣验证：公司邮箱一次性验证码，或上传 fiche de paie 工资单 / 合同（**自动打码后人工确认，确认后立即删除原件**）
- 发评价前提醒用户"描述事实，避免点名个人、不发布未证实的指控"
- 审核流水线：
  1. 自动检测：个人姓名 / 电话等 PII、辱骂用词、重复刷评（同设备、同 IP 段、文本相似度）
  2. 风险评价进入人工队列，比如涉及刑事指控、点名具体个人
  3. 举报 → 48 小时内处理；被举报的内容在处理期间可暂时隐藏
- 防刷：新账号的评价延迟发布；公司短时间内集中出现好评时降低权重并标注

### 5.5 用户功能

- 关注公司 → 有新评价或风险标签变化时，通过微信**订阅消息**提醒（需用户逐次授权）
- 分享卡片：公司档案可以一键分享到微信群或好友，卡片只展示官方事实区数据和风险标签，不展示评价原文
- 求职笔记：私人记录投递状态（v2）
- 内容至少 1 条才能解锁全部薪资数据（give-to-get 机制，⚠️ 需评估对留存的影响）

## 6. 非功能需求

| 类别 | 要求 |
|---|---|
| **法律合规（最高优先级）** | ① 平台以 **hébergeur（托管方）** 身份运营，适用 LCEN 的有限责任：收到"明显违法内容"的通知后迅速下架。② 遵守法国关于在线评价的信息披露义务（Code de la consommation L111-7-2 及 2017 年相关法令）⚠️ 需律师确认是否适用于雇主评价：公示审核规则、是否经过验证、排序方式。③ 设立通知—下架（notice & takedown）流程和法律联系人。④ 上线前请法国律师审查（诽谤 diffamation / 诋毁 dénigrement 风险）。⑤ 遵守 DSA（欧盟《数字服务法》）对在线平台的透明度和通知机制要求。 |
| **微信平台合规** | ① 小程序主体资质：确认法国非营利协会能否以**海外主体**注册小程序，以及"用户评价 / 社区"类目需要哪些资质 ⚠️（这是决定项目能否上线的头号问题）。② 遵守《微信小程序平台运营规范》中关于用户生成内容、"曝光 / 揭露"类内容的限制 ⚠️：可能不能在小程序里直接使用"黑榜"字样，或需要调整为"风险提示"。③ UGC 必须接入微信内容安全接口（msgSecCheck）做文本检测，再加上自建审核。④ 小程序审核会检查展示内容，所以提审版本只展示事实区，评价区灰度开放。 |
| **跨境数据** | 用户数据（评价、验证信息）只存放在欧盟服务器，**不使用微信云开发存储个人数据**。小程序直接调用欧盟后端的 HTTPS 接口；需确认海外主体配置服务器域名的要求 ⚠️。隐私协议里要说明：微信登录会产生腾讯侧的数据处理。 |
| **GDPR / 隐私** | 数据存放在欧盟；最小化收集；评价不关联可识别身份；验证文件处理完立即删除；提供数据导出和删除权；如有必要向 CNIL 备案或开展 DPIA（数据保护影响评估）。 |
| **匿名性** | 职位和部门很小众时自动泛化，例如"某小团队的 Data Scientist"改写成"技术岗"，防止被反推身份；时间只精确到年。 |
| **数据爬取合规** | **不爬** Glassdoor / Indeed / LinkedIn 的内容（违反服务条款）。只用开放数据（Licence Ouverte）和用户原创内容。 |
| 性能 | 公司页从中国大陆和法国访问的 P95 都 < 2s（欧盟服务器 + CDN 缓存公开的事实区数据）；主包体积 < 2MB，用分包加载；SIRENE 数据每周增量同步，BODACC 每日同步。 |
| 无障碍 | 字号可调、颜色对比达到 WCAG AA；风险标签同时用颜色 + 文字表示，不只靠颜色。 |

## 7. 用户故事（MVP）

1. 作为留学生，我收到一个 stage offer，想**输入公司名，30 秒内看到**它是否在营、有没有进入清算程序、往届实习生给的评分和转正率。
2. 作为外籍求职者，我想**筛选出"有签证担保记录"的数据公司**，优先投这些公司。
3. 作为离职员工，我想**匿名写一条评价**，并确信公司无法通过评价内容认出我。
4. 作为 offer 比较者，我想**把 2–3 家公司并排对比**薪资、评分和风险标签。
5. 作为被评价的公司，我想**公开回应**一条我认为不准确的评价，并能通过正规渠道举报违法内容。

## 8. MVP 范围

**包含（v1，约 10–12 周 ⚠️）**
- SIRENE + BODACC + Egapro 数据接入，覆盖**巴黎大区**全部在营的雇员公司（先只导入有雇员的公司，以控制数据量）
- 微信小程序：公司页（事实区 + 评价区 + 风险标签）、搜索（含中文别名）、基础筛选
- 评价提交（含基础结构化字段）、微信登录、公司邮箱验证
- 自动审核（微信内容安全接口 + 自建规则）+ 简易人工审核后台（网页版，只给志愿审核员使用）、举报流程
- 分享卡片
- 评分方法论、审核规则、隐私协议、法律声明页面

**不包含（后续版本）**
- 薪资数据区和 give-to-get（v1.1，需要先攒够数据量）
- 面试经验区、签证担保记录（v1.1）
- 对比功能、订阅消息提醒（v1.2）
- 扩展到里昂、图卢兹等其他大区（视巴黎大区的内容密度而定）
- 不做：法语 / 英语界面、网页版、原生 App、雇主账号、任何付费功能

## 9. 技术方案建议（供讨论）

- **小程序前端**：原生小程序框架，或 Taro（React 语法），方便以后需要时复用到 H5；用 TDesign 小程序组件库
- **后端**：FastAPI（或 NestJS）+ PostgreSQL（主数据，用 `pg_trgm` 做法语公司名模糊搜索，另建中文别名表）；必要时引入 Meilisearch
- **微信对接**：`code2Session` 换 openid（只存哈希）；`msgSecCheck` 文本安全检测；订阅消息（v1.2）
- **数据管道**：定时任务从 SIRENE API、BODACC 和 Egapro 的开放数据集拉取（按巴黎大区八省的邮编和省代码过滤），写入 `company`、`legal_event`、`equality_index` 表
- **审核**：规则引擎 + 基于 LLM 的 PII / 指控检测（只做辅助打分，最终由人工决定）；审核后台是一个简单网页，只对审核员开放
- **部署**：欧盟区域的托管服务（如 Scaleway / OVH，便于 GDPR 合规），前面加 CDN 改善国内访问速度；非营利项目可以申请这些厂商的公益或初创资助 ⚠️

核心数据模型（简化）：

```
company(siren PK, name, brand_names[], naf, size_band, city, status, idcc, updated_at)
legal_event(id, siren FK, type[procedure|sanction|...], date, source_url)
equality_index(siren FK, year, score)
review(id, siren FK, user_id FK, contract_type, role_bucket, city, year_from, year_to,
       is_current, ratings jsonb, pros, cons, advice, lang, verified bool, status, created_at)
visa_report(id, siren FK, user_id FK, permit_type, year, verified bool)
report(id, review_id FK, reason, status, handled_at)
```

## 10. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 被公司起诉诽谤 | 高 | hébergeur 定位、快速下架流程、事实和观点分区、黑榜只用官方数据、律师审查、购买职业责任险 |
| 冷启动缺内容 | 高 | 先用开放数据把"事实区"做满，让平台没有评价也有用；从中文留学生社群（学联、校友群、小红书）定向邀请贡献；先聚焦巴黎大区和 Tech/Data 行业 |

## 13. 微信平台可行性调研（2026-10-10）

> 调研方式：网页搜索。本次所在环境**无法直接打开微信官方站点**，下面的结论来自搜索摘要、微信开放社区问答和第三方文章，**正式决定前必须在 mp.weixin.qq.com 后台或通过官方客服复核**。

### 13.1 发现

| # | 问题 | 发现 | 可信度 |
|---|---|---|---|
| 1 | 法国主体能否注册小程序？ | 微信支持境外主体注册，法国在可选国家 / 地区里。但**境外主体只能以企业 / 组织身份注册**，个人不行。非营利协会是否算"组织"主体没有找到明确说明。 | 中 |
| 2 | 评价功能需要什么类目？ | 带用户发布内容（评论、留言、发帖）的小程序要做 **UGC 声明**，并通常要求 **"社交-社区/论坛"类目**。 | 高 |
| 3 | 该类目的资质 | 官方类目说明里，"社区/论坛"类目要求提供《**非经营性互联网信息服务备案核准**》（即 ICP 备案），政府主体可用机构代码证代替。**法国协会无法办理 ICP 备案**（需要中国主体和境内服务器）。另有开发者反馈：首次提交该类目会进入网信部门的二次审核报备流程。 | 中高 |
| 4 | 小程序备案 | 2023 年起境内小程序必须备案。2023 年 11 月官方运营人员回复称：境外主体小程序**暂未明确备案要求**，未备案暂不影响上线。2025–2026 年也有文章称面向大陆用户的跨境小程序需要备案，说法互相矛盾。 | 低 |
| 5 | 后端放在欧盟 | 境外主体使用境外域名和服务器可以配置；ICP 备案只针对境内托管。但如果有大陆用户，仍可能适用中国《个人信息保护法》（PIPL）。 | 中 |
| 6 | 内容风险 | 《微信小程序平台运营规范》有"侵犯名誉 / 商誉 / 隐私 / 肖像"专门条款；被投诉后一般先要求整改，严重时限制功能甚至下架。公司可以通过微信的侵权投诉渠道直接投诉小程序。 | 高 |
| 7 | 前车之鉴：看准网 | 国内的公司点评平台看准网已于 **2024 年 9 月 30 日停止服务**。媒体分析的原因是：评价真假难核实（公司刷好评、匿名不实差评引发舆论风波），以及盈利模式不清。 | 中 |

### 13.2 结论

1. **"官方事实区"可以做成小程序。** 它是只读的公开数据查询，属于工具类，不涉及用户发布内容，以法国主体注册的可行性较高。
2. **"评价区"放进法国主体的小程序大概率走不通**：社区类目要 ICP 备案，而且有网信部门的二次审核；就算换成国内主体，也要承担境内内容监管、名誉权投诉和数据出境（数据存欧盟）的多重合规成本，非营利项目很难负担。
3. 看准网的教训印证了第 4 节的原则：**证据优先、验证评价、不依赖广告和雇主收费**。

### 13.3 备选架构（待决定）

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **A（推荐）小程序只读 + H5 承载评价** | 小程序（法国主体，工具类目）只展示官方事实区、风险标签（只用官方数据）和统计后的评分；写评价、看评价原文放在欧盟托管的 H5 网站上，通过公众号文章或复制链接进入 | 小程序上线的可能性最高；UGC 完全在欧盟、受法国法律管辖，符合原来的 hébergeur 定位 | 微信内打开外部 H5 体验差（可能要求复制到浏览器）；小程序里能否显示由 UGC 算出的评分仍需确认 ⚠️ |
| B 只做 H5 / PWA | 放弃小程序，网站在微信群和小红书里传播 | 最简单、法律管辖最清楚 | 失去小程序的分享卡片和"用完即走"的体验 |
| C 国内主体小程序 | 找国内企业作为主体，办 ICP 备案，申请社区类目 | 体验最完整 | 法律责任落在国内合作方；数据需境内存储，与 GDPR 和匿名承诺冲突；非营利项目难以维持 |

### 13.4 下一步需要人工核实的事项

1. 在 mp.weixin.qq.com 用"境外主体 → 法国"走一遍注册流程，确认：非营利协会能否注册、可选的服务类目里有没有"社交-社区/论坛"、工具类目的具体名称。
2. 方案 A：在开放社区提问"小程序里展示汇总评分（不展示原文）是否算 UGC"。
3. 咨询律师：法国协会运营、服务对象包含中国大陆用户时，是否需要满足 PIPL 的要求。
